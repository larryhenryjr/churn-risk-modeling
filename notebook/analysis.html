Churn Risk Modeling¶

Leakage-aware classification and monthly-charge modeling

A curated public analysis by Larry Henry Jr.

TL;DR¶

This case study combines churn classification with monthly-charge regression. The historical KNN experiment improved from 82.6% to 85.8% accuracy after tuning and reached 0.92 ROC-AUC. The historical random-forest regression reported MSE of 0.08 and R-squared of 0.999; because that performance is unusually strong, the public implementation emphasizes leakage-safe preprocessing and independent holdout validation before business use.

Decision question¶

Can supervised learning identify churn risk and model monthly charges while keeping preprocessing inside reusable pipelines?

Context and Methods¶

  • Split data before fitting transformations and kept preprocessing inside scikit-learn pipelines.
  • Standardized numeric variables and one-hot encoded categorical variables.
  • Evaluated K-nearest-neighbor classification with accuracy and ROC-AUC.
  • Evaluated random-forest regression with MAE, RMSE, and R-squared on held-out observations.

Key assumptions¶

  • Evaluation preserves temporal or holdout separation where applicable.
  • Historical metrics describe the completed source analysis, not guaranteed future performance.
  • Public artifacts exclude restricted source data and institutional grading material.

Results¶

  • KNN classification: Historical tuned performance reached 85.8% accuracy and 0.92 ROC-AUC.
  • Model improvement: Hyperparameter tuning increased historical accuracy by 3.2 percentage points.
  • Charge regression: Historical results reported MSE of 0.08 and R-squared of 0.999.
  • Public implementation: Reusable pipelines isolate preprocessing from evaluation to reduce leakage risk.

Reusable Implementation¶

The public repository refactors the strongest analytical steps into typed, testable Python functions. The excerpt below is drawn from the repository implementation rather than the original working environment.

def build_preprocessor(
    frame: pd.DataFrame,
    feature_columns: list[str],
    scale_numeric: bool,
) -> ColumnTransformer:
    """Build a leakage-safe preprocessing graph from feature dtypes."""
    numeric = [column for column in feature_columns if pd.api.types.is_numeric_dtype(frame[column])]
    categorical = [column for column in feature_columns if column not in numeric]
    numeric_steps: list[tuple[str, object]] = [("impute", SimpleImputer(strategy="median"))]
    if scale_numeric:
        numeric_steps.append(("scale", StandardScaler()))
    return ColumnTransformer(
        [
            ("numeric", Pipeline(numeric_steps), numeric),
            (
                "categorical",
                Pipeline(
                    [
                        ("impute", SimpleImputer(strategy="most_frequent")),
                        ("onehot", OneHotEncoder(handle_unknown="ignore")),
                    ]
                ),
                categorical,
            ),
        ]
    )

def train_churn_classifier(
    frame: pd.DataFrame,
    feature_columns: list[str],
    target: str = "Churn",
    test_size: float = 0.25,
    random_state: int = 42,
) -> ClassificationResult:
    """Train and evaluate a K-nearest-neighbors churn classifier."""
    validate_columns(frame, feature_columns + [target])
    y = frame[target].map({"Yes": 1, "No": 0}) if frame[target].dtype == object else frame[target].astype(int)
    if y.isna().any() or y.nunique() != 2:
        raise ValueError("The churn target must contain exactly two classes.")
    x_train, x_test, y_train, y_test = train_test_split(
        frame[feature_columns],
        y,
        test_size=test_size,
        random_state=random_state,
        stratify=y,
    )
    model = Pipeline(
        [
            ("preprocess", build_preprocessor(frame, feature_columns, scale_numeric=True)),
            ("model", KNeighborsClassifier(n_neighbors=7, weights="distance")),
        ]
    )
    model.fit(x_train, y_train)
    predictions = model.predict(x_test)
    probabilities = model.predict_proba(x_test)[:, 1]
    return ClassificationResult(
        model=model,
        accuracy=float(accuracy_score(y_test, predictions)),
        roc_auc=float(roc_auc_score(y_test, probabilities)),
    )

def train_charge_regressor(
    frame: pd.DataFrame,
    feature_columns: list[str],
    target: str = "MonthlyCharge",
    test_size: float = 0.25,
    random_state: int = 42,
) -> RegressionResult:
    """Train and evaluate a random-forest monthly-charge model."""
    validate_columns(frame, feature_columns + [target])
    y = pd.to_numeric(frame[target], errors="coerce")
    if y.isna().any():
        raise ValueError("The charge target must be numeric and nonmissing.")
    x_train, x_test, y_train, y_test = train_test_split(
        frame[feature_columns],
        y,
        test_size=test_size,
        random_state=random_state,
    )
    model = Pipeline(
        [
            ("preprocess", build_preprocessor(frame, feature_columns, scale_numeric=False)),
            (
                "model",
                RandomForestRegressor(
                    n_estimators=300,
                    min_samples_leaf=2,
                    random_state=random_state,
                    n_jobs=-1,
                ),
            ),
        ]
    )
    model.fit(x_train, y_train)
    predictions = model.predict(x_test)
    return RegressionResult(
        model=model,
        mae=float(mean_absolute_error(y_test, predictions)),
        rmse=float(np.sqrt(mean_squared_error(y_test, predictions))),
    )

Interpretation and Limitations¶

  • The historical regression result is strong enough to require explicit leakage and target-proxy checks.
  • Accuracy can hide class imbalance and does not determine the business value of interventions.
  • The public repository excludes the restricted source dataset and cannot reproduce historical scores without an authorized equivalent input.

Takeaways¶

  • Revalidate against an untouched temporal holdout before using the historical performance claims operationally.
  • Choose classification thresholds using intervention capacity, recall, and expected value.
  • Audit monthly-charge predictors for post-outcome fields and direct pricing proxies.
